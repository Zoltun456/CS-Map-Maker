The plan

Most custom maps die in the art pass because the layout was never tested. Lock the layout first, then make it pretty.

  1. Layout lab. Paint the layout here, hit the timing targets, and run a few hundred simulated rounds until neither side wins much more than 55%.
  2. Blockout. Use Hammer blockout in the lab to get floor and cover coordinates, then build grey boxes in Hammer with dev textures.
  3. Bot test. Walk the map, time routes with a stopwatch, and fight bots. Fix anything that feels slow or unfair.
  4. Friends test. Play 3v3 on the grey version. Ask what felt bad, not what looked bad.
  5. Art pass. Pick a theme, swap dev textures for real materials, add props that keep cover readable.
  6. Lighting, radar, publish. Light it, make a radar image, publish it as friends-only, and play.

Set up Workshop Tools

  1. In Steam, right-click Counter-Strike 2, open Properties → DLC, and tick Counter-Strike 2 Workshop Tools. It downloads a few GB of extra content.
  2. Launch CS2 and choose Launch CS2 Workshop Tools from the launch dialog.
  3. In the tools launcher, click Create New Addon and name it after your map, for example de_saltworks. The addon is your project folder: maps, materials and models all live in it.
  4. Open the addon. The Asset Browser appears. Open Hammer from its toolbar and create a new map. Save it as maps/de_yourmap.vmap. The de_ prefix tells the game it is a bomb defusal map.

Hotkeys and menu names move around between Workshop Tools updates. When something here doesn't match what you see, the Valve Developer Community CS2 pages are the reference.

Scale and dimensions

Hammer units are roughly an inch. The lab grid uses 64-unit cells, so one cell is about the size of a standard crate.

Thing Size in Hammer units Notes
Player 32 wide, 72 tall (54 crouched) Eye height is about 64 standing.
Run speed Knife 250, AK-47 215, M4 225, AWP 200 The lab uses 220 for every timing.
Step Up to 18 Walked over without jumping. Stairs use 8 to 16 per step.
Jump About 55 standing, about 64 crouch-jump Make jump-boxes 64 tall and check them in-game.
Doorway 96 to 128 wide, 128 tall One player wide feels like a real choke.
Corridor 192 to 320 wide Three to five lab cells.
Bombsite About 512 × 384 to 768 × 640 Eight by six lab cells is a good 3v3 site.
Cover box 64 or 48 tall 48 hides a crouching player; 64 hides more but can be jumped.
Walls 256 to 384 tall Taller than anyone can boost over.

Blockout in Hammer

Hammer in Source 2 builds with editable meshes instead of the old brushes. You draw a box, then pull its faces, cut it, and extrude it.

  • Block tool (Shift+B) draws boxes. Set the grid to 16 or 32 with [ and ] and keep every wall on that grid.
  • Selection modes are on 1 to 4: vertices, edges, faces, whole meshes. Select a face and drag with Shift held to extrude it.
  • Build the floor from the lab's floor rectangles first, then put walls on their edges, then cover boxes. Use the coordinates from Hammer blockout: the map is centred on 0,0 and north is +Y.
  • Use dev materials (search dev in the Material Browser) so measurement grids stay visible. Give each team's side a different dev colour so testers can tell where they are.
  • Close off the outside of the map with walls and a ceiling or skybox. Nothing should look into the void.

Gameplay entities

These are the pieces that make it a playable bomb map. Place point entities with the Entity tool (Shift+E). Area entities are a mesh tied to an entity: draw a box, give it the toolstrigger material, select it, and use Tie to Entity (Ctrl+T).

Entity What it does For 3v3
info_player_terrorist T spawn point Place 5 so a 3v3 always has spares. Keep them 64u apart.
info_player_counterterrorist CT spawn point Same: 5, spaced out.
func_bomb_target Area where the bomb can be planted One per site. The lab's site rectangles are the extents.
func_buyzone Area where players can buy One over each spawn. Set its team.
env_sky, light_environment Sky and sun See lighting.

When you build the map (F9), make sure the navigation mesh is included in the build options, or bots will stand still.

Playtest with bots

Load the map from the console with the competitive game mode. Wingman mode caps teams at two players, so 3v3 runs in competitive with a few settings changed.

  • noclip flies through walls; cl_showpos 1 shows your coordinates so you can match them with the lab.
  • bot_stop 1 freezes bots, which is useful for checking what each angle can see.
  • Time every route with a stopwatch at full run. If a real time is more than a couple of seconds off the lab's number, your Hammer geometry has drifted from the plan.

Materials and props

Stock content first

CS2 ships with every material and prop from its official maps. In the Asset Browser, filter by materials or models/props and type a theme word like dust, italy, ancient or anubis. Drag props straight into Hammer. A themed map built only from stock content still looks professional.

Custom textures

  • Free CC0 texture sets: Poly Haven and ambientCG. Download the colour, normal, roughness and ambient occlusion maps.
  • Put the image files in your addon's content/materials/ folder, open the Material Editor, create a material with a CS2 environment shader, and plug each map into its slot.
  • Keep texel density close to the stock maps so your walls don't look blurry next to Valve's props.

Custom models

Model in Blender, export FBX, and import with ModelDoc. Give anything players touch a simple physics hull. For most cover, a stock crate or a mesh built in Hammer is faster and plays better.

Keep it readable

  • Busy textures at head height hide player models. Keep the band from 0 to 80 units calm and mid-toned.
  • Any prop that looks like cover must act like cover. Give clutter clear collision or none.
  • Mark sites with big painted letters and a recognisable landmark so callouts come naturally.

Lighting and mood

  • env_sky with a sky material, plus light_environment for the sun. Match the sun angle to the sky.
  • Cover the playable space with an env_combined_light_probe_volume so players and props pick up the bounce light.
  • Add fog and colour grading last, through a post-processing volume. Never let fog shorten a sightline you designed.
  • Avoid hard dark corners where a player blends in. Both teams should see each other equally at every common angle.

Publish and play 3v3

  1. Make a radar image. The lab's Top-down image is a starting point; the game reads the radar from an overview file in resource/overviews/ plus an image, and the VDC wiki has the current format.
  2. Publish from the Workshop Tools publishing tool. Add a preview image and set visibility to Friends only or hidden, so only people with the link can find it.
  3. Each friend subscribes on the Workshop page. The lobby host starts it from Play → Workshop Maps with the party together.
  4. Once in, the host pastes these settings for a short 3v3 match:
mp_roundtime_defuse 1.5
mp_c4timer 40
mp_freezetime 10
mp_buytime 20
mp_maxrounds 16
mp_startmoney 800
mp_limitteams 0
mp_autoteambalance 0
bot_kick
mp_warmup_end
mp_restartgame 1

3v3 design rules

  • Two sites only if rotations are short. With three CTs, one site is often held by a single player. A CT rotation over about 14 seconds means that player always dies alone.
  • Two entrances per site. Three entrances are too many for three defenders to watch.
  • CTs set up first. CTs should reach each site 5 to 10 seconds before the Ts. Check it in the timing table.
  • First contact around 6 to 12 seconds. Earlier feels like a spawn fight; later feels empty.
  • Break long sightlines. Anything over about 3000 units turns into an AWP lane. Add a doorway, a bend, or a box.
  • No spawn peeks. Neither spawn should see the other. The lab warns you when they can.
  • Small is fine. A good 3v3 map is roughly 3000 to 3600 units across. Bigger maps feel empty with six players.
